# 流萤社区 · 互动功能落地方案 v1

> 目标版本：0.9.64+135（0.9.63 沉浸式房间与双人同步继续保留；0.9.64 修正自己的主页与今日状态选择）
>
> 原则：一次只做一个可独立验收的互动；每步先跑后端真实链路与 Flutter 组件/截图验证，再进入下一步；全部完成后做一次端到端整体验收和双端出包。

## 0. 范围与取舍

本轮新增 8 个互动能力，全部围绕“用户之间产生连接”，不重复已有能力：

1. 情绪反应条（同感 / 笑死 / 抱抱 / 学到了 / 蹲后续）
2. 接一句 + 神评楼
3. 每日一问 + 连签/萤火
4. 短视频弹幕
5. 小萤接话
6. 戳一戳 + 今日状态
7. 语音评论
8. 一起听 / 一起看房间

已有能力不重复建设：点赞、收藏、评论、图片评论、表情包、投票、私信语音输入、关注、签到、任务、等级、通知、WS 实时私信。

### 统一约束

- 所有写接口必须登录、限流、敏感词检查；公开读取接口只返回审核通过内容。
- 不新增绕过现有权限的入口；作者/管理员权限复用现有 `community_admins` 与帖子归属判断。
- 所有新表使用 `community_*` 前缀，幂等建表 + `_migrate()` 加列；不改音乐共享表。
- 客户端所有乐观更新必须有失败回滚；重复点击/迟到结果不能污染新状态。
- 遵守 `prefers-reduced-motion`：位移/缩放降级为淡入，不阻塞操作。
- 新素材使用“流萤”Q 版代言人，统一银白双马尾、薄荷绿瞳/开衫、白色水手裙、红心徽章、萤火虫发夹、耳机；不生成带文字、水印、第三方 logo 的素材。

## 2. 功能设计与验收

### 2.1 情绪反应条

**用户路径**：帖子卡片底部看到 5 个流萤表情 + 计数 → 点一个 → 贴纸弹跳、计数滚动、轻触感 → 再点同一个取消；换一个则旧反应取消、新反应生效。详情页与卡片状态同步。

**数据**：`community_post_reactions(post_id, user_id, type, created)`，主键 `(post_id,user_id)`，一个用户对一条帖子只能有一个反应。`type` 限定五类。

**接口**：
- `PUT /post/<id>/reaction` body `{type}`：幂等切换；返回 `{reactions:[{type,count,mine}], myReaction}`。
- `DELETE /post/<id>/reaction`：取消；返回同上。
- `decorate_post` 增加 `reactions` 聚合与 `myReaction`；旧客户端忽略新字段。

**UI**：`post_card.dart` 互动行下新增 32dp 高的反应条；`post_detail.dart` 同步；贴纸选中态 1.0→1.12→1.0（220ms），计数 `RollingText`。空计数也显示贴纸，保证可发现。

**验收**：
- 后端：未登录 401；非法 type 400；切换后旧 type 计数减一、新 type 加一；同一用户重复 PUT 不重复计数。
- 前端：点按/取消/切换三条路径；失败回滚；快速连点 5 次最终状态与最后一次意图一致；390/320 不溢出。
- 截图：卡片反应条默认/选中、详情页选中。

### 2.2 接一句 + 神评楼

**用户路径**：作者发帖时可留一句“接一句”引子（≤40 字，可空）；卡片显示引子 + “接一句”按钮；点开评论面板时引子置顶，输入框提示“接一句…”。评论按点赞/作者置顶排序，帖子详情出现“神评楼”前三名；作者可置顶/取消置顶自己的帖子评论。

**数据**：`community_post_prompts(post_id PK, prompt, created_by, created, active)`；评论复用现有表。新增 `community_post_comments.author_pinned` 或复用 `pinned`，但管理员置顶与作者置顶分开记录，避免互相覆盖（新增 `author_pinned INTEGER DEFAULT 0`）。

**接口**：
- `PUT /post/<id>/prompt` 作者设置/清空。
- `PUT /comment/<id>/author-pin` 作者置顶/取消。
- `GET /post/<id>/comments?sort=hot` 返回 `hot` 列表（点赞降序、作者置顶优先）；默认仍按时间，向后兼容。
- `decorate_post` 返回 `prompt`；评论返回 `authorPinned`。

**验收**：
- 非作者设置引子 403；空引子清除；长度校验。
- 评论热序稳定：同赞数按时间倒序；作者置顶在最前；管理员置顶不丢。
- UI：引子展示、空引子无占位、评论面板引子/输入提示、详情神评楼前三、作者置顶操作。
- 截图：有引子卡片、评论面板、神评楼。

### 2.3 每日一问 + 连签/萤火

**用户路径**：首页/发现区出现“今日一问”卡，点进去看问题与已有回答；用户用文字或图片回答（复用评论能力），当日首次回答点亮萤火；连续参与天数显示在卡片/我的页。每天 20:00 推送一次（站内通知，不发系统推送）。

**数据**：
- `community_daily_questions(day PK, question, post_id, created)`；当天懒创建一条由“流小萤”发布的帖子，`community_posts.daily_day` 标记。
- 回答即该帖评论；`community_daily_answers(day,user_id,comment_id,created)` 记录参与，保证一人一天只算一次连签。
- 连签复用 `community_signins` 的 `day`，新增 `streak` 计算函数；萤火经验 `EXP_RULES["daily_answer"]`。

**接口**：
- `GET /daily/question` 返回今日问题、帖子 id、参与人数、我是否回答、连续天数。
- `POST /daily/answer` body `{content,images}`：写评论 + 参与记录 + 经验；重复回答允许评论但不重复计连签。
- `GET /daily/streak` 返回最近 30 天与当前连续天数。

**验收**：
- 并发首次 GET 只创建一条当日问题（唯一键/INSERT OR IGNORE）。
- 同一用户多次回答只加一次连签经验；跨天连续 +1，断签重置 1。
- UI：390/320 卡片、答题面板、我的页连签条；空回答/图片回答；失败重试。
- 截图：每日一问卡、答题态、连签页。

### 2.4 短视频弹幕

**用户路径**：短视频播放时右上角弹幕开关；开启后评论以时间轴弹幕飘过，点弹幕可查看/回复；发送弹幕 30 字内，默认当前播放秒。进度条显示高光弹幕点。

**数据**：`community_danmaku(id,post_id,user_id,content,time_ms,created,status)`；索引 `(post_id,time_ms)`。
**接口**：`GET /post/<id>/danmaku?from=&to=` 拉时间窗；`POST /post/<id>/danmaku` 发送；WS `danmaku` 实时广播给同帖在线用户（可选，先轮询/刷新也可用）。
**验收**：时间窗边界、限流、敏感词、开关持久化；视频横竖屏/暂停/切页不串弹幕；发送失败不吞输入；390/320 不遮挡播放控件；截图。

### 2.5 小萤接话

**用户路径**：帖子详情底部“让小萤接一句”；点击后生成 1 条带“AI”标识的评论草稿，用户可编辑/发送/换一句；不自动发布。私信里可“帮我想三句回复”。

**实现**：复用 `af_core` 的模型配置与安全过滤，新增 `POST /post/<id>/ai-reply`，输入帖子正文+最近评论，输出 ≤60 字；客户端展示在输入框，不直接写库。
**验收**：未登录 401；限流；输出敏感词二次过滤；模型失败回退本地候选句；不产生自动评论；AI 标识可见；截图。

### 2.6 戳一戳 + 今日状态

**用户路径**：私信双击对方头像触发“戳一戳”，全屏流萤贴纸动画 + 系统消息；个人主页可设置今日状态（一个表情 + 12 字），好友在私信/主页可一键“抱抱/加油”。

**数据**：`community_user_status(user_id PK, mood, text, updated)`；`community_pokes(id,from_uid,to_uid,created,read)`；每对用户每日最多 3 次。
**接口**：`GET/PUT /status`；`POST /poke/<uid>`；`GET /pokes/unread`。
**验收**：自戳拒绝；频率限制；WS 推送；状态仅自己/关注者可见（沿用 profile_visible）；动画不阻塞聊天；截图。

### 2.7 语音评论

**用户路径**：评论面板麦克风按住录音（≤15 秒，上滑取消），松手上传并发送语音评论；气泡显示波形、时长、播放/暂停；支持文字+语音混排（语音优先展示）。
**数据**：`community_post_comments.audio`、`audio_duration` 迁移加列；音频文件 `community_audio_*`；上传魔数/大小/时长校验。
**接口**：`POST /upload-audio`；评论接口接受 `audio` + `audioDuration`（与图片/表情包互斥规则扩展）。
**验收**：录音权限拒绝有提示；上滑取消不发送；15s 自动停止；音频可播放/暂停/进度；弱网重试；敏感内容审核；截图。

### 2.8 一起听 / 一起看

**用户路径**：私信里发起“一起听/一起看”邀请卡；对方加入后进入同步房间，房主选曲/选视频，成员同步播放、暂停、拖动；房间内飘反应，退出即结束。仅私信一对一，不做公开房。
**数据**：`community_together_rooms(id,kind,host_uid,guest_uid,media_id,media_url,position_ms,playing,started_at,updated,status)`；WS `room_state` / `room_event`。
**接口**：`POST /together/room` 创建；`POST /together/room/<id>/join`；`POST /together/room/<id>/sync`；`GET /together/room/<id>`。
**验收**：房主/成员权限；断线重连以服务器 `position_ms + (now-started_at)` 校准；暂停/拖动一致；媒体不可用降级提示；退出清理；截图。

4. 构建：Android `assembleRelease` + `apksigner verify`；iOS CI `build ios --no-codesign` + IPA `Info.plist`/arm64/资源校验。
5. 发布前检查：版本号、素材是否打进包、灰度开关（若需要）、回滚路径、SHA256。

## 5. 风险与回滚

- **数据兼容**：全部新表/新列向后兼容；旧客户端忽略未知字段。
- **内容安全**：反应/弹幕/语音/AI 均走敏感词与人工举报通道；弹幕与语音另加频率限制。
- **实时房间**：只做一对一私信房；WS 不可用时降级为“手动同步”按钮，不阻塞聊天。
- **发布门**：任一步截图/测试失败，版本不发布；已发布版本保留上一版安装包与数据库备份。
